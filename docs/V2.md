# Regenerist v2 — character sheets

v2 is a D&D Beyond–style character sheet: import or build characters, roll everything, track the table, manage inventory, play with a party, and (optionally) regenerate. It lives alongside the original Regenerist app, which is still at `/regenerist`.

## Run it

Node 22, PostgreSQL, and the local `data/` folder (not in git).

```sh
npm ci
npm run data:rules      # builds data/rules/rules-2014.json and rules-2024.json (downloads 2024 data once)
npm run dev
```

`data:rules` reads your local 5etools files for 2014 and downloads the 2024 Free Rules data from `github.com/nick-aschenbach/dnd-data` into `data/vendor/` the first time. Rerun it after changing anything in `data/`. The builder and Regenerist mode need these packs; the sheet, import, and inventory work without them.

### Upgrading an existing database (Unraid)

Back up first. Both scripts only add tables and columns:

```sh
psql "$DATABASE_URL" -f prisma/upgrades/20261106_player_character.sql
psql "$DATABASE_URL" -f prisma/upgrades/20261107_accounts_parties.sql
psql "$DATABASE_URL" -f prisma/upgrades/20261108_import_backup.sql
```

(or `docker compose exec -T db psql -U postgres -d regenerist < prisma/upgrades/<file>.sql`). Run `npm run data:rules` in the checkout before `docker compose up --build`, because the image copies `data/` from the build context.

## What's where

| Path | What |
| --- | --- |
| `/` | Your characters, D&D Beyond import, new character, parties |
| `/c/[slug]` | The sheet |
| `/new`, `/c/[slug]/build` | Builder and level-up (builder characters only) |
| `/party`, `/party/[id]` | Parties, invite codes, DM view, live roll feed |
| `/login`, `/account` | Sign-in (optional), admin account management |

| Code | What |
| --- | --- |
| `lib/sheet/types.ts` | `CharacterDoc` (what a character is) and `PlayState` (HP, uses, slots, conditions) |
| `lib/sheet/compute.ts` | Rules engine: every number on the sheet, derived from doc + state |
| `lib/import/ddb.ts` | D&D Beyond JSON → `CharacterDoc` |
| `lib/rules/*` | Rules packs, builder (`Build` → `CharacterDoc`), random builds |
| `lib/sheet/docOps.ts` | Validated inventory/currency edits (shared by client and server) |
| `lib/catalog/items.ts` | Item catalog from local 5etools data |
| `lib/auth.ts`, `lib/campaigns.ts` | Accounts, sessions, parties, roll feed |
| `scripts/build-rules.cjs` | Builds the rules packs |
| `tests/sheet-flynnwrath.test.cjs` | Golden test: a real D&D Beyond export must match D&D Beyond's numbers |

Bonuses, proficiencies, resistances and senses are all `Effect`s using D&D Beyond's modifier vocabulary, so imports are lossless and builder characters use the same engine.

## Leaving D&D Beyond

An imported character can become an app character: sheet menu → **Edit here instead of D&D Beyond**. `lib/rules/fromImport.ts` turns the imported sheet into builder choices (species, background, classes, ASIs by level, skills, expertise, optional features, spells) and checks the result against the imported numbers. Anything the rules can't reproduce is carried over and listed on the Review step, where it can be removed: extra proficiencies and languages, effects (`build.adjustments`), an HP difference (`build.hpBonus`), species/feat/item spells and custom actions (`build.kept`, server-controlled), and unknown features (`build.customFeatures`). Saving keeps the import in `PlayerCharacter.importBackup`; **Restore D&D Beyond version** puts it back. A converted character can't be re-synced from D&D Beyond.

## Accounts

With no accounts the app is open (single user, LAN). Creating the first account at `/login` makes you admin, gives you every existing character, and turns sign-in on for everyone. Admins add players at `/account`. Owners edit their characters; party members can view each other's sheets read-only; the DM sees the party page with HP, AC, conditions, and every roll live.

## Known gaps

- **2024 subclasses.** The 2024 data has no subclass text, so 2024 builder characters enter subclass features by hand (Class step). 2014 has all 136 subclasses. Imports from D&D Beyond include everything the character has.
- **2024 feats.** Only origin feats are described; other feats can be named but have no rules text or automation.
- **Feature automation.** Common numeric effects are automated (Rakish Audacity, Unarmored Defense, Jack of All Trades, Aura of Protection, Reliable Talent, crit ranges, Alert, Tough, …). Choices such as Fighting Style, Eldritch Invocations, Metamagic and Maneuvers show their text but aren't selectable yet.
- **Spell lists.** 102 Xanathar's/Tasha's spells have no class list in the local data; the builder offers them under "include spells with no class list".
- **Species spells in the builder** (e.g. Tiefling Infernal Legacy) are described in traits but not added as castable spells. Imported characters have them.
- **Conditions text** comes from the SRD 5.1 (2014 wording) via `github.com/adkinn/srd-5.2.1`, which is labelled 5.2.1 but carries the older text.
- **Regeneration story** uses AWS Bedrock with the model in `BEDROCK_MODEL_ID` and falls back to a local story. The old default (Claude 3.5 Sonnet, 2024) is likely retired; set `BEDROCK_MODEL_ID` to a current Claude model available in your Bedrock account.
- **Converting 2024 characters** from D&D Beyond is only as complete as the 2024 pack: subclass features and non-origin feats come over as custom features with D&D Beyond's text. Only Flynnwrath (2014) has been checked end to end.
- **Old Regenerist characters** (Character/Life tables) are not converted to v2 yet; they remain available at `/regenerist`.
